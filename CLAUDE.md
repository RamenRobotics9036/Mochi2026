# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is the FRC (FIRST Robotics Competition) robot codebase for Team 9036 (RamenRobotics), 2026 season. It is a Java/WPILib command-based robot project using a CTRE Phoenix 6 swerve drivetrain, Limelight vision, and PathPlanner autonomous routines.

## Build & Development Commands

```bash
# Build the project
./gradlew build

# Run tests
./gradlew test

# Run a single test class
./gradlew test --tests "frc.robot.visutils.TestVisionKalmanFilter"

# Run tests with JaCoCo coverage report
./gradlew test jacocoTestReport -PjacocoEnabled

# Run simulation (desktop)
./gradlew simulateJava

# Deploy to robot (must be connected)
./gradlew deploy

# Build without tests
./gradlew assemble
```

## Architecture

### Entry Points
- `Robot.java` — `TimedRobot` subclass; manages mode lifecycle and calls `CommandScheduler`
- `RobotContainer.java` — centralizes all subsystem instantiation, IO selection (real vs. sim), and controller bindings
- `Main.java` — Java entry point, do not modify

### Multi-Robot Support (`botconfig/`)
The codebase supports two physical robots detected by RoboRIO MAC address at runtime:
- **Competition Bot** (`CompConfig`) — uses `GeneratedCompConstants`
- **Pancake (Practice Bot)** (`PancakeConfig`) — uses `GeneratedPancakeConstants`
- **Simulation** — defaults to `CompConfig`

`RobotIdentity.getBotConfig()` returns a `BotConfigInterface` that abstracts all robot-specific constants (swerve module geometry, camera transforms, speed limits, etc.). Always use the interface, never reference a specific config class directly.

### IO Abstraction Pattern
Every hardware subsystem has a real and simulated IO interface:
- `XxxIoReal` — communicates with real hardware (CAN motors, encoders)
- `XxxIoSim` — WPILib physics simulation backend

`RobotContainer` selects the correct implementation with `Robot.isSimulation()`. `SimIoFactory` is a centralized factory for creating sim IOs with the right constants from `Constants.java`.

### Subsystems (`subsystems/`)
| Subsystem | Hardware |
|-----------|----------|
| `CommandSwerveDrivetrain` | CTRE Phoenix 6 swerve (extends `TunerSwerveDrivetrain`) |
| `ShooterSubsystem` | Two REV SparkFlex motors + hood servo |
| `IndexerSubsystem` | Single roller motor |
| `IntakeSubsystem` | Single roller motor |
| `ArmSubsystem` | Dual-motor arm with position control and homing |
| `ClimberSubsystem` | Single motor elevator |
| `SpinnyWheels` | Always-on oscillating wheel |

### Vision System (`visutils/`)
Vision is built around Limelight cameras using MegaTag2 pose estimation:
- `MultiCamOdometry` — iterates over all cameras each cycle, picks best-locked camera
- `SingleCamOdometry` — reads one Limelight's NetworkTables data and feeds `drivetrain.addVisionMeasurement()`
- `VisionKalmanFilter` — vision-only Kalman filter for precise stationary pose estimation (requires ≥2 tags, resets when robot moves)
- `MotionlessTracker` — detects when robot is stationary; triggers Kalman filter reset on movement
- `AimController` — PID-based auto-aim while driving (POV Up on driver controller)

Camera configurations (names + robot-to-cam transforms) live in `BotConfigInterface.getCameras()`.

### Simulation (`sim/`)
- `SimWrapper` — unified sim wrapper; null on real robot (use `SimWrapper.create()`)
- `GroundTruthSim` — tracks the "true" robot pose for physics simulation
- `VisionSim` / `PhotonToLimelightConverter` — simulates AprilTag detection via PhotonVision and publishes as Limelight NetworkTables data
- `SimIoFactory` — creates subsystem sim IOs

Sim bindings: D-pad Right injects odometry drift, D-pad Left cycles robot reset position.

### Autonomous (`subsystems/auto/`)
PathPlanner is used for autonomous path following. `AutoLogic` (static utility class) manages the dashboard chooser and command creation. Named commands are registered in `RobotContainer.registerNamedCommands()`. Paths/autos are stored in `src/main/deploy/pathplanner/`.

### Constants
All tunable values live in `Constants.java` as nested static classes (e.g., `Constants.IntakeConstants`, `Constants.ArmConstants`). Robot-specific drivetrain constants are in `generated/GeneratedCompConstants.java` and `generated/GeneratedPancakeConstants.java` (generated by CTRE Tuner X — avoid editing manually).

### Vendor Libraries
- `Phoenix6` — CTRE TalonFX motors, CANcoders, Pigeon IMU, swerve drive
- `PathplannerLib` — autonomous path following
- `photonlib` — AprilTag vision simulation
- `REVLib` — REV SparkFlex/SparkMax motor controllers
